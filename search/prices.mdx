Read every venue's current price for a pair from prices TetraFi already holds, without asking any venue.

Prices are fast, use no quote limit and are never firm: use them to compare venues and size a trade, then trade at a live price or request quotes.

<View title="In the app" icon="browser">

## At a glance

<Steps>
  <Step title="Set the pair">
    In **Trade**, choose what **You pay** and **You receive**, and an amount.
  </Step>
  <Step title="Read the prices">
    The prices card shows each venue's current price, marked **Live** or **Indicative**.
  </Step>
  <Step title="Trade">
    On a **Live** price, select **Trade at the live price**, then **Confirm order**. Otherwise select **Request quotes** ([Request quotes](/search/how-it-works)).
  </Step>
</Steps>

</View>

## At a glance

Both need [Read quotes](/authentication#permissions) (`prices_read`).

| Endpoint | Result |
| --- | --- |
| [`GET /api/v1/prices`](/api-reference/trading/get-prices) | One row per venue, location and variant pair, sorted like quotes. |
| [`GET /api/v1/prices/stream`](/api-reference/trading/stream-prices) | A `snapshot` server-sent event when a watched pair changes. |

- Use prices to show prices, size a trade or choose venues, then [request quotes](/search/how-it-works) to trade.
- No venue is asked, so it is fast and does not use the [quote limit](/reference/rate-limits).
- A price is never firm: no row has `quality: firm`. A row with `tradable: true` can be ordered directly by its `priceId`, within your `minReceive` or `slippageBps` ([Live prices](/trade/live-prices)); every other row is traded through a [quote](/trade/request-for-quote).
- A venue that publishes no price (`priceSourceNone`) answers only a quote request.

  <Accordion title="Row fields">

Rows that hold no price come last.

<ResponseField name="sizes[]" type="object[]">One entry per size you asked for: `sell`, `buy` (after included fees; `null` when nothing could be priced), `netReceived`, `filled` (`full`, `partial` or `none`) and `fees`.</ResponseField>
<ResponseField name="basis" type="string">`levels` (the venue's published levels) or `model`.</ResponseField>
<ResponseField name="observedAt, staleAfter" type="string">When the price was seen, and when it is old.</ResponseField>
<ResponseField name="levels" type="object[]">The venue's own price levels, in sell units, where it publishes them. Read them as `ladderSemantics` says.</ResponseField>
<ResponseField name="ladderSemantics" type="string">Present whenever `levels` is. `incremental`: levels add up, and a size walks them best first; each level is `size` more sell units at `price`. `allIn`: each level prices exactly its own total `size`, and a size takes the smallest level at or above it.</ResponseField>
<ResponseField name="spreadFromMidBps" type="object">The spread from the reference mid at the first size, or `unavailable` with a reason, never 0.</ResponseField>
<ResponseField name="referenceMid" type="object | null">The pair's reference price. `null` when it could not be read, with the reason in `referenceMidUnavailable`.</ResponseField>
<ResponseField name="computedAt" type="string">When this snapshot was built; it is reused for about a second.</ResponseField>
<ResponseField name="sellBalances" type="array">Always empty for an API key.</ResponseField>

  </Accordion>
  <Accordion title="Row statuses">

| `status` | Meaning |
| --- | --- |
| `priced` | A current price. |
| `stale` | Past `staleAfter`, or the source is warming up. Any price it holds is kept. |
| `unsupported` | `pairNotServed`, `priceSourceNone` (only a quote request asks it) or `buyAmountUnsupported`. |
| `belowMin`, `insufficientDepth` | The first size is below the venue's minimum, or more than it can fill. |
| `needsWallet`, `restricted` | The venue prices only for a wallet, or a permission keeps the price from you. |
| `unavailable` | A read failed, or a fee could not be worked out; `reason` says which. |

Treat a value you do not know as other ([Conventions](/reference/conventions#values)).

  </Accordion>
  <Accordion title="Caching, streaming and limits" id="caching-streaming-and-limits">

- Each response carries an `ETag`: send it back in `If-None-Match` to get `304 Not Modified` when nothing changed.
- `GET /api/v1/prices/stream` watches up to 25 pairs (`pairs=USDC:ETH,USDC:EURC` instead of `sell` and `buy`) and sends a `snapshot` server-sent event when a pair changes. Each caller may hold 4 streams at once.
- Price reads have their own limit: `429 RATE_LIMITED` with `details.limit` `prices`, or `priceStreams` for a fifth stream, both with `Retry-After`.

</Accordion>
</AccordionGroup>

## Refusals

<Accordion title="Price refusals">

| Status and code | Why, and what to do |
| --- | --- |
| `400 ASSET_UNKNOWN`, `NETWORK_UNKNOWN`, `VENUE_UNKNOWN` | A value is not in the catalogue. Use values from `GET /api/v1/assets`. |
| `400 AMOUNT_INVALID` | An amount or a size is not a positive decimal. Send positive decimals. |
| `400 SAME_ASSET_NEEDS_NETWORK` | `sell` and `buy` are the same asset with no chain pinned. Add `sell.network` or `buy.network`. |
| `400 INVALID_REQUEST` | Both amounts, `sizes` with an amount, no amount at all, or an unknown parameter, such as `pay`, `receive`, `amount` or `side`. Send `sell`, `buy` and one of `sellAmount`, `buyAmount` or `sizes`. |
| `403 INSUFFICIENT_SCOPE` | The key lacks `prices_read`. Use a key with Read quotes. |
| `429 RATE_LIMITED` | Too many price reads (`details.limit` `prices`), or streams (`priceStreams`). Wait `Retry-After` seconds, or close a stream. |
| `503 PRICES_ELIGIBILITY_WARMING` | Your workspace's prices are still loading. Retry after `Retry-After` (about 1 second). |

</Accordion>
