Each quote says whether its venue is bound to the price, in `firm` and `expiresAt`. A search returns every kind unless you ask for firm quotes only.

| Field | Value | Effect |
| --- | --- | --- |
| `filters.firmOnly` | `true`, or `false` (the default) | With `true`, only quotes with `firm: true` are kept in `quotes`. |

## Firm, executable and indicative

| `firm` and `expiresAt` | What it means | What you can rely on | Kept by `firmOnly` |
| --- | --- | --- | --- |
| `firm: true`, `expiresAt` set | Firm: the venue delivers exactly this amount until `expiresAt`. | The quoted amount. | Yes |
| `firm: false`, `expiresAt` set | An executable estimate, such as an order-book or AMM quote: the venue will trade until `expiresAt`, and delivery may move a little. | At least `minOut`, set by your [price protection](/search/sort-and-protection#price-protection). | No |
| `firm: false`, `expiresAt` `null` | Indicative: the venue's current price, not a commitment. `staleAfter` says when the price is old. | Nothing yet. | No |

Ask for firm quotes only when you are about to trade and want to compare only amounts a venue has committed to. Leave it out when you are comparing prices, or when an order book, a pool or a desk that publishes only indicative prices may give you the best one: an executable estimate is still protected by `minOut`.

To turn an indicative quote into a firm one, requote it: see [Requotes and expiry](/trade/requotes-and-expiry).

The cURL block is an excerpt from the quote-only [`search-filters.sh` script](https://github.com/tetrafi/docs/blob/main/samples/http/search-filters.sh). Run that script with the [Quickstart credentials](/quickstart#set-your-environment): it defines `sell`, `buy`, `amount` and `quote_request`, the helper that sends a signed quote request and waits once if the quote rate limit is reached. The excerpt is not a standalone shell script.

## What you see for the quotes you leave out

Quotes that are not firm are dropped after venues answer, so this filter does not keep any venue from being asked. A venue that gave only estimates or indicative prices still reads `answered` in `sources`, but has no quote in `quotes`:

```json
{
  "quotes": [
    { "id": "q_...", "firm": true, "expiresAt": "2026-11-03T02:39:35.040Z" }
  ],
  "sources": [
    { "status": "answered", "venue": { "id": "...", "modality": "rfq" }, "asked": true, "detail": null },
    { "status": "answered", "venue": { "id": "...", "modality": "orderBook" }, "asked": true, "detail": null }
  ]
}
```

Here two venues answered and one quote is left: the order book's quote was an estimate. The sample prints those venues: an `answered` source with no quote.

Because the same venues are asked, a search with `firmOnly: true` counts against the [quote limit](/search/how-it-works#rate-limit) exactly as it would without the filter.

## Refusals

| Code | Why | What to do |
| --- | --- | --- |
| `INVALID_REQUEST` | `firmOnly` is not `true` or `false`, with `details.field` `filters.firmOnly`. | Send a boolean. |
| `INVALID_REQUEST` | The request names the filter's earlier name, `filters.executableOnly`. | Send `filters.firmOnly` instead. |

## In the app

The trade page has no control for this filter. A shared link can carry it in its `firm` parameter, and it then shows as a **Firm only** chip you can remove; it is then sent with the request.

The results list also has a commitment toggle and an **All types** select. They only filter the quotes already returned, so nothing is sent and no venue is asked again.
