[Multilateral Netting](/netting) clears debts by **atomic multilateral set-off** across one network. Integrating means bringing your obligations, signing once, and funding only your net when a run asks.

## Quick Reference

| Facet | |
| --- | --- |
| Protocol | REST over HTTPS, plus push events to your webhook |
| Credential | Workspace API key (`X-API-Key`); `Idempotency-Key` on every write |
| Signature | One EIP-712 envelope per obligation, carried by Permit2 or ERC-3009 |
| On-chain steps | Signing is off-chain; beyond a one-time Permit2 approval per token, you never call a clearing contract to submit or settle |
| Settlement | Lock your net, commit, release only along debts you signed |
| Guarantee | A debt only ever gets smaller; nothing pays out before the run commits |
| Effort | Five touchpoints, the same for every book |

**The shape:** [five touchpoints](/netting-api/integration) - onboard, submit obligations, sign once, act on each run, reconcile.

## Your Own Policy Domain

* **One network, configured - not run.** Modularity means configuring your participation, not running the engine.
* **Your policy domain** - counterparty sets, deadline-tier menu, backstop configuration, funding mode, perimeter policy, and visibility slice.
* **Your infrastructure or ours** - the clearing service is packaged to run on your institution's own infrastructure, or alongside a backend you already operate.
* **Fees:** [Monetization](/core-concepts/monetization#fees-on-the-next-layers).
