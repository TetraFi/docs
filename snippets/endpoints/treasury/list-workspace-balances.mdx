| | |
| --- | --- |
| **Recorded** | Reads no chain or venue without `no-cache`; unread accounts are in `unreachable`, never zero. |
| **Permission** | Keys need `treasury_read`; a wallet's policy must allow `read_balances`. |
| **Filters** | `asset`, `accountKind`, `accountId` and `network` (exact CAIP-2). |
| **Paging** | `limit` and `cursor` until `nextCursor` is null ([Paging](/reference/conventions#paging)). |

<Accordion title="no-cache: read the venue now">
`Cache-Control: no-cache` with `accountId` naming exactly one venue account reads that venue now and answers its rows from the reading. Without one, or with another kind of account, it is 400 `INVALID_REQUEST` naming `Cache-Control`. A venue that refuses the read answers its named error, such as `VENUE_CONNECTION_INVALID`.
</Accordion>

<Accordion title="Sort, fields and include">
- Sort with `sort` set to `field` or `-field`, where field is `id` (the default), `accountId`, `asset`, `network`, `valueUsd` (unvalued rows last either way) or `observedAt`.
- `fields` restricts the row fields but always keeps `id`, `accountId` and `asset`.
- `include=account` adds each row's account by `accountId`, as that account's own read answers it, or null with its refusal.
</Accordion>

<Accordion title="Which accounts you see">
- Venue accounts need View wallets in a company or broker workspace, or an admitted LP taker.
- Personal wallets are never listed. Accounts hidden from you change neither the rows nor the cursors.
- A cursor is bound to the workspace, the caller, the filters, the sort and the visible rows in order. If accounts change while you page, start again without a cursor.
</Accordion>

<Accordion title="Example response">
```json From the spec expandable
{
  "items": [
    {
      "accountId": "22222222-2222-4222-8222-222222222222",
      "accountKind": "venueAccount",
      "amount": "25000.00",
      "asset": "USDC",
      "available": "24000",
      "expiresAt": "2026-11-18T14:05:00Z",
      "freshness": "fresh",
      "id": "bal_01JB05EXW3MBMS1QSQJS0ZWPNQ",
      "locked": "1000",
      "network": null,
      "observedAt": "2026-11-18T14:00:00Z",
      "source": "providerApi",
      "valueUsd": "24998.75",
      "valuedAt": "2026-11-18T14:00:01Z"
    }
  ],
  "nextCursor": null,
  "unreachable": []
}
```

| Field | What it tells you |
| --- | --- |
| `accountKind`, `accountId` | The wallet or venue account holding the row. |
| `amount`, `available`, `locked` | Everything held, in whole units; what can be spent or moved now; what the provider holds back. `available` and `locked` are null when unknown. |
| `observedAt`, `expiresAt`, `source` | When the source observed it, when that reading stops being current, and where it came from. |
| `freshness` | `fresh`, `stale` or `partial`: how current the recorded balance is. |
| `valueUsd`, `valuedAt` | US dollar value at the market-data display price (up to eight decimals), and when that price was observed. Without a price both are null, never zero. |
| `unreachable` | Accounts this read could not state, repeated on every page. |

For totals rounded to cents and daily history, read `GET …/balances:aggregate`.
</Accordion>

<Accordion title="Refusals">
| Status and code | Why, and what to do |
| --- | --- |
| 400 `BALANCE_LIST_QUERY_INVALID` | An unknown or malformed parameter. Send only the listed parameters. |
| 400 `LIMIT_INVALID`, `CURSOR_INVALID` | Send a `limit` from 1 to 100, or start again without a cursor. |
| 403 `INSUFFICIENT_SCOPE` | The key lacks `treasury_read`. Use a key that holds it. |
| 403 `OBSERVATION_AUTHORITY_REQUIRED` | The credential has no current authority to read this. Restore its Treasury read access. |
| 403 `WALLET_ACCESS_CHANGED` | Your access changed while the answer was built. Read again. |
| 403 `WORKSPACE_ACCESS_REQUIRED` | The key's owner left the workspace. Use a current member's key. |
| 409 `VENUE_ACCOUNT_ELIGIBILITY_CHANGED` | An account was disconnected mid-read; nothing was released. Read again. |
| 503 `INVENTORY_UNAVAILABLE`, `VENUE_ACCOUNT_ELIGIBILITY_UNAVAILABLE` | Nothing was released. Retry shortly, with backoff. |
</Accordion>
