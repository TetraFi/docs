| | |
| --- | --- |
| **Paging** | `limit` 1 to 100 (default 50); follow `nextCursor` until `null`. |
| **Recorded only** | Lists what TetraFi recorded; this read never asks the LP or the chain. |
| **LP unreachable** | One `unreachable` entry (source `lpHistory`); recorded movements are still listed. |
| **Owner** | The key's owner also needs View settlements ([Permissions](/authentication#permissions)). |

<Accordion title="How current: include=observation">
`include=observation` returns how current the movements are in `included.observation[venueAccountId]`: `lastSuccessfulReadAt`, `observationState`, `reasonCode` and `observationRequestedAt`.

TetraFi reads every active account in the background, on its own schedule. A signed-in member asks for a fresh read with a create on `settlement/observations`.
</Accordion>

<Accordion title="Refusals">
| Status and code | Why, and what to do |
| --- | --- |
| 400 `SETTLEMENT_MOVEMENT_LIMIT_INVALID` | `limit` is outside 1 to 100. |
| 403 `INSUFFICIENT_SCOPE` | The key lacks `settlements_read`. |
| 403 `WORKSPACE_PERMISSION_REQUIRED` | The key's owner lacks View settlements. `details.fix` names who can grant it. |
| 404 `VENUE_ACCOUNT_NOT_FOUND` | No venue account with this id in your workspace. |
| 404 `SETTLEMENT_MOVEMENT_NOT_FOUND` | No window with the `windowId` filter's id on this account. |
| 503 `SETTLEMENT_MOVEMENTS_ACCOUNT_UNAVAILABLE` | The account could not be read for its movements. Retry shortly. |
</Accordion>
