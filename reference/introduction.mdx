Every operation an API key can call, generated from the API's own specification. Start with the [Quickstart](/quickstart) if you are integrating for the first time; the [Compatibility policy](/compatibility) says what can change after launch.

## Base URL and authentication

| Environment | Base URL |
| --- | --- |
| Sandbox | `https://api-dev.tetrafi.io` |
| Production | `https://api.tetrafi.io`, from launch |

Send your API key in `X-API-Key` on every request: the key implies its workspace. A key with venue trading also signs each request ([Authentication](/authentication)). [Environments](/overview#environments) lists what differs in the sandbox.

## Supported interfaces

| Interface | What you can use |
| --- | --- |
| REST | JSON over HTTP under `/api/v1`. |
| Server-sent events | `POST /api/v1/quotes` with `Accept: text/event-stream` streams a new search ([JSON or a stream](/search/how-it-works#json-or-a-stream)); a requote answers JSON. `GET /api/v1/prices/stream` streams prices. |
| Webhooks | Workspace events, including `order.updated` ([Webhooks](/trade/webhooks)). |
| FIX | Not supported. |

A quote stream reports the search, never an order's outcome: follow orders by their status or webhooks. The API needs no SDK; a TypeScript SDK is coming soon to npm.

## Download the specification

Download the [OpenAPI specification](https://raw.githubusercontent.com/TetraFi/docs/main/api-reference/openapi.json) (OpenAPI 3.1, JSON) to generate a client or import it into your tools. The [Changelog](/changelog) lists each change.

## Postman collection

<Steps>
  <Step title="Import the collection">
    Import the [TetraFi Postman collection](https://raw.githubusercontent.com/TetraFi/docs/main/api-reference/tetrafi.postman_collection.json) with **Import → Link**.
  </Step>
  <Step title="Set your variables">
    Set these values locally in its **Variables** tab:

    | Variable | Value |
    | :--- | :--- |
    | `baseUrl` | The base URL of your environment |
    | `apiKey` | Your API key |
    | `signingSecret` | The key's 64-character hexadecimal signing secret, if signing is enabled |
  </Step>
  <Step title="Check your credentials">
    Send **GET /api/v1/assets**. The collection signs each request when `signingSecret` is set.
  </Step>
</Steps>

<Warning>
The collection includes order placement. Replace angle-bracket placeholders and path variables before sending, and send requests one at a time. Never share or export it with values filled in.
</Warning>

## Reading responses

- Ignore response fields you don't recognise; objects can gain fields.
- Treat an enum value you don't recognise as "other": every response enum is open.
- Every refusal is one error body ([Errors and refusals](/trade/errors), [Error codes](/reference/error-codes)).

Read each field's schema for its time format:

| Field | Format |
| --- | --- |
| Quote `expiresAt`, `observedAt`, `staleAfter`; order `settlesBy`; error `timestamp` | RFC 3339 date-time in UTC, or `null` where the schema allows it. |
| A continuation repricing offer's `expiresAt` | Integer Unix seconds, unlike the quote's `expiresAt`. |
| `requestExpiryMs`, when present | Integer Unix milliseconds. |
| `eta`, `retryAfter` | ISO 8601 durations. |

[Conventions](/reference/conventions) covers amounts, ids, pagination, headers and versioning.
