These rules hold on every endpoint, so implement them once. The examples order nothing.

## Requests

| Rule | Detail |
| --- | --- |
| Base URL | `https://api.tetrafi.io`, or `https://api-dev.tetrafi.io` in the [sandbox](/overview#environments). Every path starts with `/api/v1`. |
| Credentials | `X-API-Key` on every request, plus a signature when request signing is on ([Authentication](/authentication)). |
| Workspace | The key implies its workspace, so `X-Workspace-Id` is optional. When sent, it must be the key's own. |
| Bodies | JSON, sent with `Content-Type: application/json`. |

## Values

| Value | Form | Example |
| --- | --- | --- |
| Amounts | Decimal strings, never JSON numbers. Parse with a decimal type, not a float. | `"10.0147"` |
| Amount precision | At most the asset's decimals. More is refused with `400 AMOUNT_PRECISION_EXCEEDED` (`details.field`, `details.decimals`, `details.allowed`) before any quote or funding check. | |
| Times | RFC 3339, in UTC. | `"2026-10-30T00:40:13.162Z"` |
| Durations | ISO 8601. | `"PT2S"` |
| Chains | CAIP-2 chain ids. | `"eip155:8453"` |
| Field names | camelCase. | `expiresAt` |
| Ids | Opaque strings. Store and compare them whole; never parse. | `"q_01JAY7Q5M3ZK8V2N4R6T8W0XYB"` |
| Enumerations | Open sets that can gain values. Treat an unknown value as "other". | `"status": "answered"` |

## Paging

A list that pages takes `limit` and answers `nextCursor`. Send it back unchanged as `cursor` until `nextCursor` is absent or `null`.

| Rule | Detail |
| --- | --- |
| Opaque tokens | Never decode, construct or edit them; their encoding is not part of the contract. |
| Same list only | Use a token only for the same workspace, list and filters. |
| Expired or invalid token | Tokens may expire, including after a server-key rotation or private-format deployment. An invalid or expired authenticated cursor answers 400: restart without `cursor`. |
| Snapshot lists | A list with a snapshot contract may answer `409 CURSOR_STALE` after the underlying selection changes: restart from its first page. |
| `GET /api/v1/assets` | 1 to 200 assets a page. |
| `GET /api/v1/orders` | Up to 20 orders a page; a page can hold fewer than `limit`, even none, while more follow. |

## Errors

| Rule | Detail |
| --- | --- |
| One body | Every refusal carries `error`, `message`, `requestId`, `timestamp`, `docUrl`, and `next` and `details` when they apply. |
| One status per code | Each code has one HTTP status. `docUrl` links its entry in the [error-code reference](/reference/error-codes). |
| Match on `error` | Never on `message`. |

[Errors and refusals](/trade/errors) shows how to read one.

## Request ids

| Rule | Detail |
| --- | --- |
| Every response | Carries `X-Request-Id`; a refusal repeats it as `requestId`. Quote it to support. |
| Your own id | Send `X-Request-Id` (up to 64 letters, digits, `-` and `_`) to trace a request in your logs and ours; the response echoes it. |
| Invalid id | Replaced with a generated UUID, which the response carries instead. |

## Rate limits and idempotency

| Rule | Detail |
| --- | --- |
| Rate limits | Every limit answers `429` with `Retry-After` ([Rate limits](/reference/rate-limits)). |
| Idempotency | Send an `Idempotency-Key` with every `POST /api/v1/orders`. A retry with the same key and body returns the first answer, with `Idempotent-Replayed: true` ([Retries and recovery](/trade/retries-and-recovery)). |

## Read several resources at once

`POST /api/v1/batch` runs up to 20 reads in one request. Use it to load a page of related resources in one round trip.

| Rule | Detail |
| --- | --- |
| Items | 1 to 20 `{id, method, url}`. `method` is `GET`; `url` is the path and query of a `GET` operation in this reference, such as `/api/v1/orders?limit=20`. |
| Authority | Each item runs as its own `GET` by the same caller: same permissions, scopes, workspace checks, body and error body. |
| Rate limit | Each item counts as one request, all taken before any item runs. A `429 RATE_LIMITED` refuses the whole batch. |
| Answer | `200` once admitted, items in request order. Items are independent, not atomic. |
| Not batchable | Signed API-key requests: send those reads separately. |

<Accordion title="Item answers, limits and whole-batch refusals">

| Rule | Detail |
| --- | --- |
| Item answer | Each item returns `id`, `status`, `etag`, `body` and, when sent, `headers` (`Deprecation`, `Sunset`, `Link`, `Retry-After`, `Cache-Control`). |
| Limits | Item bodies total at most 8 MiB (past it an item answers `413 BATCH_RESPONSE_TOO_LARGE`), and at most 200 reads with related reads (past it `429 SUB_REQUEST_BUDGET_EXHAUSTED`). |
| Refused as a whole | A malformed batch, more than 20 items, a non-`GET` item, an unknown operation, or a stream, export or file read. `details.itemId` names the item. |

</Accordion>

## Versioning

The API is versioned in its path, `/api/v1`. After launch, changes within a version are additive: new operations, optional fields, headers, enumeration values and error codes.

A removal is announced in the changelog at least 6 months ahead. Until it happens, every answer of the affected operation, successes and refusals alike, carries three headers.

<Accordion title="Deprecation headers">

| Header | Meaning |
| --- | --- |
| `Deprecation` | When the operation was deprecated: `@` and Unix seconds, such as `@1735689600` ([RFC 9745](https://www.rfc-editor.org/rfc/rfc9745)). |
| `Sunset` | When it stops working, as an HTTP date such as `Tue, 01 Jul 2025 00:00:00 GMT` ([RFC 8594](https://www.rfc-editor.org/rfc/rfc8594)). |
| `Link` | The notice that says what to move to, marked `rel="deprecation"`. |

</Accordion>

No operation is deprecated today, so no answer carries them yet; log any answer that does. Before launch, a change can still remove or rename something.

See the full [Compatibility](/compatibility) policy and the [Changelog](/changelog).
