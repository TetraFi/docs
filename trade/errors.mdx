Every refusal is the same JSON object, whatever the status and whichever call you made, including `413` and `415` answers. One parser reads them all. The [error-code reference](/reference/error-codes) lists every code; this page shows how to read one and what to do.

The examples come from [`samples/http/errors.sh`](https://github.com/tetrafi/docs/blob/main/samples/http/errors.sh), which provokes three refusals and places no order.

## Read a refusal

```json
{
  "error": "QUOTE_EXPIRED",
  "message": "This quote has expired, so nothing was sent. Request a new price.",
  "requestId": "5ee4d511-5ef8-4e47-9999-5b144ec4fcbc",
  "timestamp": "2026-10-19T20:56:39Z",
  "docUrl": "https://tetrafi.mintlify.app/reference/error-codes#QUOTE_EXPIRED",
  "next": { "kind": "requote", "needs": [] }
}
```

| Field | What to do with it |
| --- | --- |
| `error` | The stable code. Match on it. |
| `message` | A sentence for people. Show or log it, never match on it. |
| `requestId` | The `X-Request-Id` response header. Log it and quote it to support. |
| `timestamp` | When it was refused, in RFC 3339 UTC. |
| `docUrl` | The code's entry in the error-code reference. |
| `next` | The way forward, when there is one ([below](#what-next-tells-you)). |
| `details` | The code's detail, when it has any. Read the camelCase keys you know; more can appear. `details.value` names a refused value, `details.reason` a token saying why, and `details.retryAfter` how long to wait. |

## What next tells you

| `next.kind` | What to do |
| --- | --- |
| `requote` | Send `POST /api/v1/quotes` with `{"kind":"requote","requote":"<quote id>"}`. `next.needs` lists what the new quote needs, such as a wallet; empty means requote as it is ([Requotes and expiry](/trade/requotes-and-expiry)). |
| `fund` | The paying account holds too little. Fund it, then get a new price. |
| `order` | The quote can be ordered as it is. |
| `preflight`, `sign`, `transact` | Advanced steps, not open yet. Order a Basic quote instead. |

Treat a `kind` you do not recognise as a step you cannot take automatically: show `message` and stop.

## Retries

| Answer | Retry? |
| --- | --- |
| `429` | Yes, after `Retry-After` ([Rate limits](/reference/rate-limits)). |
| `503` | Yes, after `Retry-After` when it is set, otherwise after a second or two, with backoff. A signed write signs again with a new `X-Timestamp` and `X-Nonce`. |
| `408`, `500`, `502`, `504` | Yes, with backoff. |
| `409` | Only where the code says so, such as `ORDER_IN_PROGRESS`. Otherwise the state has to change first. |
| Any other `4xx` | No. Fix the request, or act on `next`. |

A wait comes twice: the `Retry-After` header in whole seconds, and `details.retryAfter` as an ISO 8601 duration, which can carry a fraction such as `PT1.5S`. Sending sooner is refused again.

Retry an order only with the same `Idempotency-Key` and body. When you do not know whether it was placed, never send it with a new key ([Retries and recovery](/trade/retries-and-recovery)).

## Codes you do not know

New codes can be added at any time. Treat one you do not know by its status class, as the [compatibility policy](/compatibility#what-your-client-should-do) says: retry a `429` or `503` after `Retry-After`, retry a `5xx` with backoff, and fix the request on any other `4xx`. Show `message` and log `requestId` either way.

## The wrong workspace

A key may leave `X-Workspace-Id` out. When it sends one, it must be the key's own: another workspace answers `403 WORKSPACE_SCOPE_MISMATCH`, and a value that is not a workspace id `400 INVALID_WORKSPACE_ID`. A path under `/api/v1/workspaces/{workspaceId}/` that names a workspace that is not yours answers `404 WORKSPACE_NOT_FOUND`, exactly as one that does not exist.

A workspace that cannot trade yet answers `403 CAPABILITY_BLOCKED`, naming each thing to fix in `details.capabilityBlockers` ([Before your first trade](/before-you-trade#complete-your-company-details)).

## Refusals on any request

| Status and code | When it happens | What to do |
| --- | --- | --- |
| 401 `AUTH_REQUIRED` | The request did not authenticate. `details.reason` says why: `MISSING_CREDENTIALS`, `INVALID_API_KEY` (unknown or revoked), `API_KEY_EXPIRED`, or a [signing reason](/authentication#sign-every-request). | Act on `details.reason`; treat one you do not know as "fix the credentials". |
| 400 `MISSING_WORKSPACE` | A session, or a key bound to no workspace, sent no `X-Workspace-Id`. | Send the workspace id. |
| 400 `INVALID_WORKSPACE_ID`, 403 `WORKSPACE_SCOPE_MISMATCH`, 404 `WORKSPACE_NOT_FOUND` | The workspace header or path is malformed or not yours. | Use the `workspaceId` from `GET /api/v1/me`. |
| 403 `WORKSPACE_NOT_ACTIVE` | The workspace is suspended or deactivated. | Contact support. |
| 403 `CAPABILITY_BLOCKED`, 503 `CAPABILITY_UNAVAILABLE` | The workspace cannot do this yet, or that could not be read just now. | Fix each blocker in the app; retry a `503` shortly. |
| 403 `IP_NOT_ALLOWED` | The request came from outside the key's IP allowlist. | Send from an allowed address. |
| 403 `INSUFFICIENT_SCOPE` | The key lacks the permission this call needs. | Use a key with it ([Permissions](/authentication#permissions)). |
| 403 `INSUFFICIENT_PERMISSION` | You, the key's owner, no longer hold the permission. | Ask a workspace admin for it. |
| 403 `VENUE_TRADE_SCOPE_REQUIRED`, `VENUE_TRADE_KEY_DISABLED`, `VENUE_TRADE_SIGNATURE_REQUIRED` | The call trades on a venue account and the key lacks venue trading, has it switched off, or did not sign. | [Trade on your venue accounts](/authentication#trade-on-your-venue-accounts). |
| 403 `VENUE_TRADE_KEY_CHANGED` | The key's venue trading changed while the request ran. | Send it again. |
| 413 `REQUEST_BODY_TOO_LARGE`, 415 `UNSUPPORTED_CONTENT_TYPE` | The body is too large, or not sent as `application/json`. | Fix the body or its header. |
| 429 `RATE_LIMITED` | A request limit is used up, or TetraFi is briefly at capacity. | Wait `Retry-After` seconds. |
| 503 `API_KEY_UNAVAILABLE`, `AUTHORIZATION_UNAVAILABLE`, `KEY_AUTHORITY_UNAVAILABLE`, `VENUE_TRADE_KEY_UNAVAILABLE` | The key or workspace could not be checked just now. | Sign again with a new timestamp and nonce, then retry. |
| 408 `REQUEST_TIMEOUT`, 500 `INTERNAL_ERROR`, 503 `SERVICE_UNAVAILABLE` | The request did not complete. | Retry with backoff; quote `requestId` to support if it persists. |
