Every refusal, `413` and `415` included, is the same JSON object, so one parser reads them all: match on `error`, and act on the status class only for a code you do not know.

## Decide what to do

| Answer | What happened | What to do |
| --- | --- | --- |
| `409` conflict | It conflicts with the current state. | On an order, `QUOTE_ALREADY_ORDERED` or an `IDEMPOTENCY_*` code means an order may exist: [recover it by its quote](/trade/orders#retries-and-recovery). Otherwise retry only where the code says so, such as `ORDER_IN_PROGRESS`; else the state has to change first. |
| `429` | A request limit is used up, or TetraFi is briefly at capacity. | Retry after `Retry-After` ([Rate limits](/reference/rate-limits)), unless the code says otherwise. |
| `503` | It could not be served just now. | Recover an order by its quote first. Otherwise retry after `Retry-After`, or after a second or two with backoff when it is not set. A signed write signs again with a new `X-Timestamp` and `X-Nonce`. |
| `408`, `500`, `502`, `504` or a timeout | It did not complete, or its outcome is unknown. | Recover an order by its quote first. Otherwise retry with backoff only when the code's `retryable` is `true`. |
| Any other `4xx` | Refused. On an order this usually means nothing was placed, but not always: a replay refused with `IDEMPOTENCY_AUTHORITY_REQUIRED`, or a code whose entry says a source transaction may already be confirmed, says nothing about the first attempt. | Do not retry. On an order, [recover it by its quote](/trade/orders#retries-and-recovery) before you order again; otherwise fix the request, or act on [`next`](#what-next-tells-you). |

On an order, retry only with the same `Idempotency-Key` and body. When you do not know whether it was placed, never send it with a new key.

<AccordionGroup>
  <Accordion title="Waits and order retries">

A timeout or 5xx on an order is unknown until you [recover it](/trade/orders#retries-and-recovery). A 4xx usually placed nothing, but a refused replay or a code that says a source may already be confirmed does not prove it: recover by the quote before you order again.

- Waits: `Retry-After` is whole seconds; `details.retryAfter` is an ISO 8601 duration that can carry a fraction, such as `PT1.5S`. Sending sooner is refused again.

</Accordion>
</AccordionGroup>

## Read a refusal

Every refusal carries `error`, `message`, `requestId`, `timestamp`, `docUrl` and, when there is one, `next`. Look up codes in the [error-code reference](/reference/error-codes).

<AccordionGroup>
  <Accordion title="The body, field by field">

```json
{
  "error": "QUOTE_EXPIRED",
  "message": "This quote has expired, so nothing was sent. Request a new price.",
  "requestId": "5ee4d511-5ef8-4e47-9999-5b144ec4fcbc",
  "timestamp": "2026-10-19T20:56:39Z",
  "docUrl": "https://tetrafi.mintlify.app/reference/error-codes#QUOTE_EXPIRED",
  "next": { "kind": "requote", "needs": [] }
}
```

| Field | Use |
| --- | --- |
| `error` | The stable code. Match on it. |
| `message` | For people. Show or log it, never match on it. |
| `requestId` | The `X-Request-Id` header. Log it; quote it to support. |
| `timestamp` | When it was refused, RFC 3339 UTC. |
| `docUrl` | The code's reference entry. |
| `next` | The way forward, when there is one. |
| `details` | Optional detail. Read the camelCase keys you know; more can appear. `details.value` names a refused value, `details.reason` says why, `details.retryAfter` how long to wait. |

  </Accordion>
  <Accordion title="Example: act on a refused asset">

Act on the code of a quote for an asset TetraFi does not list:

<ErrorsParse />

```json Output
{"error":"UNKNOWN_ASSET","requestId":"5ee4d511-…","next":null,"details":{"value":"NOT_AN_ASSET"}}
use values from GET /api/v1/assets: {"value":"NOT_AN_ASSET"}
```

  </Accordion>
</AccordionGroup>

## What next tells you

`next.kind` names the way forward; a `kind` you do not recognise is a step you cannot take automatically.

<AccordionGroup>
  <Accordion title="Every next.kind">

| `next.kind` | What to do |
| --- | --- |
| `requote` | `POST /api/v1/quotes` with `{"kind":"requote","requote":"<quote id>"}`. `next.needs` lists what the new quote needs, such as a wallet; empty means requote as it is ([Requotes and expiry](/search/firmness-and-lifetime#requote-a-quote)). |
| `fund` | The paying account holds too little. Fund it, then get a new price. |
| `order` | Order the quote as it is. |
| `preflight`, `sign`, `transact` | Advanced steps, not open yet. Order a Basic quote. |

A `kind` you do not recognise is a step you cannot take automatically: show `message` and stop.

  </Accordion>
</AccordionGroup>

## Refusals on any request

<AccordionGroup>
  <Accordion title="Authentication, workspace, limits and availability">

| Status and code | When | What to do |
| --- | --- | --- |
| 401 `AUTH_REQUIRED` | Not authenticated. `details.reason`: `MISSING_CREDENTIALS`, `INVALID_API_KEY` (unknown or revoked), `API_KEY_EXPIRED`, or a [signing reason](/authentication#sign-requests). | Act on `details.reason`; treat an unknown one as "fix the credentials". |
| 400 `MISSING_WORKSPACE` | A session, or a key bound to no workspace, sent no `X-Workspace-Id`. | Send it. |
| 400 `INVALID_WORKSPACE_ID`, 403 `WORKSPACE_SCOPE_MISMATCH`, 404 `WORKSPACE_NOT_FOUND` | The workspace header or path is not a workspace id, or not yours. | Use the `workspaceId` from `GET /api/v1/me`. |
| 403 `WORKSPACE_NOT_ACTIVE` | The workspace is suspended or deactivated. | Contact support. |
| 403 `CAPABILITY_BLOCKED`, 503 `CAPABILITY_UNAVAILABLE` | The workspace cannot do this yet (each blocker in `details.capabilityBlockers`), or that could not be read. | Fix each blocker ([Before your first trade](/before-you-trade#complete-your-company-details)); retry a `503` shortly. |
| 403 `IP_NOT_ALLOWED` | Outside the key's IP allowlist. | Send from an allowed address. |
| 403 `INSUFFICIENT_SCOPE` | The key lacks this call's permission. | Use a key with it ([Permissions](/authentication#permissions)). |
| 403 `INSUFFICIENT_PERMISSION` | The key's owner no longer holds the permission. | Ask a workspace admin. |
| 403 `VENUE_TRADE_SCOPE_REQUIRED`, `VENUE_TRADE_KEY_DISABLED`, `VENUE_TRADE_SIGNATURE_REQUIRED` | A venue-account trade by a key without venue trading, with it off, or unsigned. | [Trade on your venue accounts](/authentication#trade-on-your-venue-accounts). |
| 403 `VENUE_TRADE_KEY_CHANGED` | The key's venue trading changed mid-request. | Send it again. |
| 413 `REQUEST_BODY_TOO_LARGE`, 415 `UNSUPPORTED_CONTENT_TYPE` | The body is too large, or not `application/json`. | Fix the body or header. |
| 429 `RATE_LIMITED` | A limit is used up, or TetraFi is briefly at capacity. | Wait `Retry-After` seconds. |
| 503 `API_KEY_UNAVAILABLE`, `AUTHORIZATION_UNAVAILABLE`, `KEY_AUTHORITY_UNAVAILABLE`, `VENUE_TRADE_KEY_UNAVAILABLE` | The key or workspace could not be checked. | Sign again with a new timestamp and nonce, then retry. |
| 408 `REQUEST_TIMEOUT`, 500 `INTERNAL_ERROR`, 503 `SERVICE_UNAVAILABLE` | It did not complete. | Retry with backoff; quote `requestId` if it persists. |

  </Accordion>
</AccordionGroup>
