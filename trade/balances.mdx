Read what each wallet and exchange account holds and the TetraFi fees you pay; these reads never move money.

## At a glance

Paths are under `/api/v1/workspaces/{workspaceId}`.

| Read | Permission |
| --- | --- |
| Every wallet and exchange-account balance, one row per account, asset and chain: `GET …/balances` | Treasury read |
| Your exchange accounts and their `venueAccountId`: `GET …/venue-enablements` | Treasury read |
| What the venue last reported for one account: `GET …/venue-accounts/{venueAccountId}/balances` | Treasury read |
| Where to deposit, and what was credited: `GET …/venue-accounts/{venueAccountId}/deposit-instructions` and `…/deposit-history` | Treasury read |
| [Credit and positions](/trade/settlement-and-credit#credit-and-the-ledger): `GET …/venue-accounts/{venueAccountId}/credit` and `…/ledger` | Treasury read |
| The fees in force now and every scheduled change: `GET …/fee-schedule` | Read fee schedule |

Your workspace id is the `workspaceId` from `GET /api/v1/me` ([Permissions](/authentication#permissions)).

## Every balance in one list

`GET …/balances` reads TetraFi's last observation and never asks a chain or venue. Filter with `asset`, `accountKind` and `accountId`; an account that cannot be stated is listed in `unreachable`, never as a zero row.

<AccordionGroup>
  <Accordion title="Fields and paging">
    Personal wallets are never listed; bank account balances cannot be observed.

<ResponseField name="id" type="string">Opaque: never parse or build one.</ResponseField>
<ResponseField name="accountKind" type="string">`wallet`, `venueAccount` or `bankAccount`; show an unknown kind as it is.</ResponseField>
<ResponseField name="accountId" type="string">A wallet's `walletId`, or the exchange account's `venueAccountId`.</ResponseField>
<ResponseField name="asset, network, networkRef" type="string">The asset; `network` is the CAIP-2 network, `null` off-chain (such as at an exchange) or when the source does not name exactly one; `networkRef` is the source's own network spelling.</ResponseField>
<ResponseField name="nativeAssetId" type="string">The asset's id at its source, such as a token contract, if known.</ResponseField>
<ResponseField name="amount" type="string">Everything held, a decimal string in whole units.</ResponseField>
<ResponseField name="asOf, freshness" type="string">When observed, and `fresh`, `stale` or `partial` (treat an unknown value as `stale`).</ResponseField>

Page with `limit` (1 to 100) and `cursor` until `nextCursor` is `null`; if accounts change mid-paging, restart without a cursor.

  </Accordion>
  <Accordion title="Request and response">

<BalancesList />

```json Response (shortened)
{
  "items": [
    { "id": "…", "accountKind": "wallet", "accountId": "…", "asset": "USDC", "networkRef": "eip155:84532", "network": "eip155:84532",
      "nativeAssetId": "0x036c…", "amount": "12.200749", "asOf": "2026-11-05T21:40:11Z", "freshness": "fresh" }
  ],
  "nextCursor": null,
  "unreachable": []
}
```

<BalancesFilter />

  </Accordion>
  <Accordion title="Balances that are unknown">
    `unreachable` repeats on every page: show each account in it as unavailable, not empty. Each entry has a `source` (`wallets/…`, `venueAccounts/…` or `bankAccounts/…`) and a `reason`, with `accountKind`, `accountId`, `asset` and `networkRef` when known, and the `readAt` of the source's last answer.

    An entry with `source` `accessSettings` (`reason` `accessSettingsUnavailable`) means access settings could not be read, so the list may leave accounts out. Read again shortly.

<BalancesUnavailable />

```json Response (shortened)
{
  "items": [],
  "nextCursor": null,
  "unreachable": [
    { "source": "venueAccounts/169e142e-…", "reason": "…", "accountKind": "venueAccount", "accountId": "169e142e-…" },
    { "source": "accessSettings", "reason": "accessSettingsUnavailable" }
  ]
}
```

## List your exchange accounts

`GET …/venue-enablements` lists venue accounts in `items`, oldest first, keyed by `venueEnablementId`. Read balances from a `configured` account; a `walletBased` venue trades from your wallets, so read those.

<AccordionGroup>
  <Accordion title="Fields and paging">
    Page with `limit` (20 by default, at most 100) and `cursor`.

<ResponseField name="accountId" type="string">The `venueAccountId` the reads below take. Absent for a wallet-based venue.</ResponseField>
<ResponseField name="venueKind" type="string">`accountBased` (the venue holds your money) or `walletBased` (it trades from your wallets).</ResponseField>
<ResponseField name="fundingTarget" type="object">Where the money lives: `{kind: "venueAccount", accountId}` or `{kind: "tradingWallets", walletIds}`. Treat a value you do not know as other ([Conventions](/reference/conventions#values)).</ResponseField>
<ResponseField name="venueId, label" type="string">The venue, such as `binance` (`null` if unknown), and the account's app name.</ResponseField>
<ResponseField name="lifecycle" type="string">`pending`, `configured`, `funding_only`, `disabled` or `revoked`. Treat all but `configured` as unusable.</ResponseField>
<ResponseField name="tradingStatus, withdrawalStatus" type="string">`active`, or `paused` by your workspace's control. Treat another value as not active.</ResponseField>

  </Accordion>
  <Accordion title="Request and output">

<VenueAccountsList />

```json Example output
{"accountId":"8a31ab17-…","venueId":"okx","label":"OKX account","lifecycle":"revoked","venueKind":"accountBased"}
{"accountId":"7e873d0e-…","venueId":"okx","label":"OKX account","lifecycle":"revoked","venueKind":"accountBased"}
{"accountId":"169e142e-…","venueId":"keyrock","label":"Keyrock account","lifecycle":"configured","venueKind":"accountBased"}
```

  </Accordion>
</AccordionGroup>

## One exchange account

`GET …/venue-accounts/{venueAccountId}/balances` answers what the venue last reported for the account, one line per asset.

<AccordionGroup>
  <Accordion title="Fields">

<ResponseField name="status" type="string">`supported` when readable; otherwise `reason` and `reasonCode` say why.</ResponseField>
<ResponseField name="observedAt, expiresAt" type="string">When reported, and when the reading stops being current.</ResponseField>
<ResponseField name="balances" type="array">One line per asset. `null` means no reading; `[]` means the account holds nothing.</ResponseField>
<ResponseField name="balances[].total" type="string">Everything held, locked included. Negative on a credit account: what it owes.</ResponseField>
<ResponseField name="balances[].free" type="string">Free to trade or withdraw, per the venue.</ResponseField>
<ResponseField name="balances[].available" type="string">`free` less TetraFi's commitments to open trades and withdrawals; `null` if unknown.</ResponseField>
<ResponseField name="balances[].usdValue" type="string">US dollar value; `null` without a reference price, never `0`.</ResponseField>

  </Accordion>
  <Accordion title="Request and output">

<VenueBalances />

```json Example output expandable
{"status":"supported","observedAt":"2026-11-02T13:20:05.236Z","expiresAt":"2026-11-02T13:25:05.236Z","balances":[{"asset":"SOL","total":"0.31240084","free":"0.31240084","available":"0.31240084","usdValue":"29.2500906492"},{"asset":"USDC","total":"7393.12791400","free":"7337.12791400","available":"7337.127914","usdValue":"7391.6492884172"},{"asset":"XRP","total":"15.153715","free":"15.153715","available":"15.153715","usdValue":null}]}
```

  </Accordion>
  <Accordion title="Deposits">

| Read | Answers |
| --- | --- |
| `GET …/venue-accounts/{venueAccountId}/deposit-instructions` | The asset and network pairs it takes deposits on, in `options`. |
| `GET …/venue-accounts/{venueAccountId}/deposit-history` | Deposits the venue credited for one `asset` on one `network` (CAIP-2), both required, from `from` (RFC 3339, 1 to 30 whole days back, 7 by default) until now. The credits are in `items`, oldest first; without paging, the whole window. With `limit` (1 to 200), follow `nextCursor` until `null`; a cursor keeps its window. Add `include=observation` for this read's own window (`since`, `until`), status and reason in `included.observation[venueAccountId].value`. |

Empty `items` is truly empty only when `unreachable` is empty too; otherwise the history was not read, and its one `unreachable` entry names why in `reason`. A window of more than 1,000 venue records is not read (`DEPOSIT_HISTORY_WINDOW_TOO_LARGE`): read a shorter window.

<VenueDepositHistory />

```json Example output
{"asset":"USDC","network":"eip155:11155111","status":"supported","since":"…","until":"…","deposits":0,"unreachable":[]}
```

  </Accordion>
</AccordionGroup>

<Warning>
A venue that publishes no networks answers `options: []` and lists its assets in `unconfirmedNetworkAssets`. Their networks are not verified: never send real funds on them.
</Warning>

## Fee schedule

`GET …/fee-schedule` answers the schedule in force now (`current`) and every change already scheduled (`upcoming`); it reads only. Every member can read fees, but a key needs Read fee schedule: no other permission includes it.

<AccordionGroup>
  <Accordion title="Request and response">

<FeeScheduleRead />

```json Response (shortened)
{
  "workspaceId": "36ff6481-…",
  "current": {
    "defaultRates": {
      "platform": { "ratePpm": "100", "effectiveFrom": "2026-10-27T00:00:00Z" },
      "grossPlatform": { "ratePpm": "100", "effectiveFrom": "2026-10-27T00:00:00Z" },
      "takerIncentive": null,
      "makerShare": null
    },
    "venues": [],
    "partnerArrangementApplies": false
  },
  "upcoming": []
}
```

  </Accordion>
  <Accordion title="Schedule fields and rates">

<ResponseField name="current" type="object">
  The schedule in force.
  <Expandable title="schedule">
    <ResponseField name="defaultRates" type="object">The rates every venue uses unless it is listed in `venues`.</ResponseField>
    <ResponseField name="venues" type="array">The venues whose rates differ, each with its own `rates`.</ResponseField>
    <ResponseField name="partnerArrangementApplies" type="boolean">`true` when your workspace has a partner arrangement with the venue.</ResponseField>
  </Expandable>
</ResponseField>
<ResponseField name="upcoming" type="array">
  Scheduled changes, oldest first, each with its `effectiveFrom` and the whole `schedule` from then. `[]` means none.
</ResponseField>

| Rate | Meaning |
| --- | --- |
| `platform` | Your charged rate, after any taker incentive. |
| `grossPlatform` | The rate before the taker incentive. |
| `takerIncentive` | The share of the gross fee rebated to you; `null` if none. |
| `makerShare` | The fee share you earn as the venue's partner maker; `null` if none. Never shows another workspace's arrangement. |

Each rate has `ratePpm` and `effectiveFrom`:

- `ratePpm`: a decimal string in parts per million (100 ppm is one basis point, 0.01%). Read it as a decimal, not a float.
- `effectiveFrom`: the RFC 3339 date-time it applies from.

</Accordion>
</AccordionGroup>

## Refusals

<AccordionGroup>
  <Accordion title="Balances and exchange accounts">

| Status and `error` | What to do |
| --- | --- |
| `400 INVALID_BALANCE_LIST_QUERY` | Use only `cursor`, `limit`, `asset`, `accountKind` (`wallet`, `venueAccount` or `bankAccount`) and `accountId`. |
| `400 INVALID_LIMIT`, `400 INVALID_CURSOR` | Send a valid `limit`, or start again without a cursor. |
| `403 OBSERVATION_AUTHORITY_REQUIRED`, `403 VENUE_READ_AUTHORITY_REFUSED` | The key has no current authority to read the account, or lost it mid-read. Restore its Treasury read access. |
| `403 WALLET_ACCESS_CHANGED` | The key's access changed mid-read. Read again. |
| `403 WORKSPACE_ACCESS_REQUIRED` | The key's owner left the workspace. Use a current member's key. |
| `404 VENUE_ACCOUNT_NOT_FOUND` | No exchange account with that id in the workspace. |
| `409 VENUE_ACCOUNT_ELIGIBILITY_CHANGED` | An account was disconnected mid-read. Read again. |
| `409 VENUE_ACCOUNT_REVERIFY_REQUIRED`, `409 VENUE_ACCOUNT_REVOKED` | No current venue key reads the account, or it was disconnected. Reconnect it in the app. |
| `409 VENUE_ACCOUNT_FUNDS_IN_WALLETS` | The money is in your own wallets: read those. |
| `503 INVENTORY_UNAVAILABLE`, `503 VENUE_ACCOUNT_ELIGIBILITY_UNAVAILABLE` | Retry shortly. |

  </Accordion>
  <Accordion title="Fee schedule">

| Status and `error` | What to do |
| --- | --- |
| `400 INVALID_REQUEST` | The path's workspace id is malformed. |
| `503 FEE_SCHEDULE_UNAVAILABLE` | Unreadable; no partial or zero schedule is sent. Retry shortly. |

A key without Read fee schedule is refused with `403 INSUFFICIENT_SCOPE`.

  </Accordion>
</AccordionGroup>

Every other code is in [Error codes](/reference/error-codes).
