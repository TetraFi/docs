Read what each wallet and exchange account holds and the TetraFi fees you pay; these reads never move money.

## At a glance

Paths are under `/api/v1/workspaces/{workspaceId}`.

| Endpoint | Permission | Result |
| --- | --- | --- |
| `GET …/balances` | Treasury read | Every wallet and exchange-account balance, one row per account, asset and chain. |
| `GET …/venue-enablements` | Treasury read | Your exchange accounts and their `venueAccountId`. |
| `GET …/venue-accounts/{venueAccountId}/balances` | Treasury read | What the venue last reported for one account. |
| `GET …/venue-accounts/{venueAccountId}/deposit-instructions` and `…/deposit-history` | Treasury read | Where to deposit, and what was credited. |
| `GET …/venue-accounts/{venueAccountId}/credit` and `…/ledger` | Treasury read | Credit and positions: [Credit and settlement](/trade/settlement-and-credit#credit-and-the-ledger). |
| `GET …/fee-schedule` | Read fee schedule | The fees in force now and every scheduled change. |

Your workspace id is the `workspaceId` from `GET /api/v1/me` ([Permissions](/authentication#permissions)).

## Every balance in one list

`GET …/balances` reads TetraFi's last observation and never asks a chain or venue. Filter with `asset`, `accountKind` and `accountId`; an account that cannot be stated is listed in `unavailable`, never as a zero row.

<AccordionGroup>
  <Accordion title="Fields and paging">
    Personal wallets are never listed; bank account balances cannot be observed.

| Field | Meaning |
| --- | --- |
| `id` | Opaque: never parse or build one. |
| `accountKind` | `wallet`, `venueAccount` or `bankAccount`; show an unknown kind as it is. |
| `accountId` | A wallet's `walletId`, or the exchange account's `venueAccountId`. |
| `asset`, `chain` | The asset and CAIP-2 chain; `chain` is `null` off-chain, such as at an exchange. |
| `nativeAssetId` | The asset's id at its source, such as a token contract, if known. |
| `amount` | Everything held, a decimal string in whole units. |
| `asOf`, `freshness` | When observed, and `fresh`, `stale` or `partial` (treat an unknown value as `stale`). |

Page with `limit` (1 to 100) and `cursor` until `nextCursor` is `null`; if accounts change mid-paging, restart without a cursor.

  </Accordion>
  <Accordion title="Request and response">

<BalancesList />

```json Response (shortened)
{
  "items": [
    { "id": "…", "accountKind": "wallet", "accountId": "…", "asset": "USDC", "chain": "eip155:84532",
      "nativeAssetId": "0x036c…", "amount": "12.200749", "asOf": "2026-11-05T21:40:11Z", "freshness": "fresh" }
  ],
  "nextCursor": null,
  "unavailable": []
}
```

<BalancesFilter />

  </Accordion>
  <Accordion title="Balances that are unknown">
    An account whose balance cannot be stated is listed in `unavailable` on every page: show it as unavailable, not empty. Each entry has `accountKind`, `accountId`, `asset` and `chain` when known, a `reasonCode`, and the `asOf` of the source's last answer.

    `incomplete` means the list may leave accounts out; `reason` `accessSettingsUnavailable` says access settings could not be read. Read again shortly.

<BalancesUnavailable />

```json Response (shortened)
{
  "items": [],
  "nextCursor": null,
  "unavailable": [
    { "accountKind": "venueAccount", "accountId": "169e142e-…", "asset": null, "chain": null, "reasonCode": "…", "asOf": null }
  ],
  "incomplete": { "reason": "accessSettingsUnavailable" }
}
```

  </Accordion>

## List your exchange accounts

`GET …/venue-enablements` lists venue accounts in `items`, oldest first, keyed by `venueEnablementId`. Read balances from a `configured` account; a `walletBased` venue trades from your wallets, so read those.

<AccordionGroup>
  <Accordion title="Fields and paging">
    Page with `limit` (20 by default, at most 100) and `cursor`.

| Field | Meaning |
| --- | --- |
| `accountId` | The `venueAccountId` the reads below take. Absent for a wallet-based venue. |
| `venueKind` | `accountBased` (the venue holds your money) or `walletBased` (it trades from your wallets: read those). |
| `fundingTarget` | Where the money lives: `{kind: "venueAccount", accountId}` or `{kind: "tradingWallets", walletIds}`. Treat another kind as "other". |
| `venueId`, `label` | The venue, such as `binance` (`null` if unknown), and the account's app name. |
| `lifecycle` | `pending`, `configured`, `funding_only`, `disabled` or `revoked`. Read balances from `configured`; treat others as unusable. |
| `tradePaused`, `withdrawalPaused` | Whether trading or withdrawals are paused. |

  </Accordion>
  <Accordion title="Request and output">

<VenueAccountsList />

```json Output on test networks
{"accountId":"8a31ab17-…","venueId":"okx","label":"OKX account","lifecycle":"revoked","venueKind":"accountBased"}
{"accountId":"7e873d0e-…","venueId":"okx","label":"OKX account","lifecycle":"revoked","venueKind":"accountBased"}
{"accountId":"169e142e-…","venueId":"keyrock","label":"Keyrock account","lifecycle":"configured","venueKind":"accountBased"}
```

  </Accordion>
</AccordionGroup>

## One exchange account

`GET …/venue-accounts/{venueAccountId}/balances` answers what the venue last reported for the account, one line per asset. `available` is `free` less TetraFi's commitments to open trades and withdrawals.

<AccordionGroup>
  <Accordion title="Fields">

| Field | Meaning |
| --- | --- |
| `state` | `supported` when readable; otherwise `reason` and `reasonCode` say why. |
| `observedAt`, `expiresAt` | When reported, and when the reading stops being current. |
| `balances` | One line per asset. `null` means no reading; `[]` means the account holds nothing. |
| `balances[].total` | Everything held, locked included. Negative on a credit account: what it owes. |
| `balances[].free` | Free to trade or withdraw, per the venue. |
| `balances[].available` | `free` less TetraFi's commitments to open trades and withdrawals; `null` if unknown. |
| `balances[].usdValue` | US dollar value; `null` without a reference price, never `0`. |

  </Accordion>
  <Accordion title="Request and output">

<VenueBalances />

```json Output on test networks expandable
{"state":"supported","observedAt":"2026-11-02T13:20:05.236Z","expiresAt":"2026-11-02T13:25:05.236Z","balances":[{"asset":"SOL","total":"0.31240084","free":"0.31240084","available":"0.31240084","usdValue":"29.2500906492"},{"asset":"USDC","total":"7393.12791400","free":"7337.12791400","available":"7337.127914","usdValue":"7391.6492884172"},{"asset":"XRP","total":"15.153715","free":"15.153715","available":"15.153715","usdValue":null}]}
```

  </Accordion>
  <Accordion title="Deposits">

| Read | Answers |
| --- | --- |
| `GET …/venue-accounts/{venueAccountId}/deposit-instructions` | The asset and network pairs it takes deposits on, in `options`. |
| `GET …/venue-accounts/{venueAccountId}/deposit-history` | Deposits the venue credited for one `asset` on one `chainRef` (CAIP-2), both required, over the last `lookbackDays` (1 to 30, 7 by default). Without paging, the whole window, with `since` and `until`. With `limit` (1 to 200), credits page oldest first: follow `nextCursor` until `null`; a cursor keeps its window, and a window of more than 1,000 credits answers none, so read a shorter one. |

In the history, `credits: null` means it could not be read; `[]` is truly empty. Over 1,000 venue records answers no credits with `reasonCode` `DEPOSIT_HISTORY_WINDOW_TOO_LARGE`: read a shorter window.

<VenueDepositHistory />

```json Output on test networks
{"asset":"USDC","chainRef":"eip155:11155111","state":"supported","reason":"Terminal credits reported by this venue account in the displayed window. Refresh balances separately before requesting a fresh RFQ.","credits":0}
```

  </Accordion>
</AccordionGroup>

<Warning>
A venue that publishes no networks answers `options: []` and lists its assets in `unconfirmedNetworkAssets`. Their networks are not verified: never send real funds on them.
</Warning>

## Fee schedule

`GET …/fee-schedule` answers the schedule in force now (`current`) and every change already scheduled (`upcoming`); it reads only. Every member can read fees, but a key needs Read fee schedule: no other permission includes it.

<AccordionGroup>
  <Accordion title="Request and response">

<FeeScheduleRead />

```json Response (shortened)
{
  "workspaceId": "36ff6481-…",
  "current": {
    "defaultRates": {
      "platform": { "ratePpm": "100", "effectiveFrom": "2026-10-27T00:00:00Z" },
      "grossPlatform": { "ratePpm": "100", "effectiveFrom": "2026-10-27T00:00:00Z" },
      "takerIncentive": null,
      "makerShare": null
    },
    "venues": [],
    "partnerArrangementApplies": false
  },
  "upcoming": []
}
```

  </Accordion>
  <Accordion title="Schedule fields and rates">

<ResponseField name="current" type="object">
  The schedule in force.
  <Expandable title="schedule">
    <ResponseField name="defaultRates" type="object">The rates every venue uses unless it is listed in `venues`.</ResponseField>
    <ResponseField name="venues" type="array">The venues whose rates differ, each with its own `rates`.</ResponseField>
    <ResponseField name="partnerArrangementApplies" type="boolean">`true` when your workspace has a partner arrangement with the venue.</ResponseField>
  </Expandable>
</ResponseField>
<ResponseField name="upcoming" type="array">
  Scheduled changes, oldest first, each with its `effectiveFrom` and the whole `schedule` from then. `[]` means none.
</ResponseField>

| Rate | Meaning |
| --- | --- |
| `platform` | Your charged rate, after any taker incentive. |
| `grossPlatform` | The rate before the taker incentive. |
| `takerIncentive` | The share of the gross fee rebated to you; `null` if none. |
| `makerShare` | The fee share you earn as the venue's partner maker; `null` if none. Never shows another workspace's arrangement. |

Each rate has `ratePpm` and `effectiveFrom`:

- `ratePpm`: a decimal string in parts per million (100 ppm is one basis point, 0.01%). Read it as a decimal, not a float.
- `effectiveFrom`: the RFC 3339 date-time it applies from.

</Accordion>
</AccordionGroup>

## Refusals

<AccordionGroup>
  <Accordion title="Balances and exchange accounts">

| `error` | Status | What to do |
| --- | --- | --- |
| `INVALID_BALANCE_LIST_QUERY` | 400 | Use only `cursor`, `limit`, `asset`, `accountKind` (`wallet`, `venueAccount` or `bankAccount`) and `accountId`. |
| `INVALID_LIMIT`, `INVALID_CURSOR` | 400 | Send a valid `limit`, or start again without a cursor. |
| `OBSERVATION_AUTHORITY_REQUIRED`, `VENUE_READ_AUTHORITY_REFUSED` | 403 | The key has no current authority to read the account, or lost it mid-read. Restore its Treasury read access. |
| `WALLET_ACCESS_CHANGED` | 403 | The key's access changed mid-read. Read again. |
| `WORKSPACE_ACCESS_REQUIRED` | 403 | The key's owner left the workspace. Use a current member's key. |
| `VENUE_ACCOUNT_NOT_FOUND` | 404 | No exchange account with that id in the workspace. |
| `VENUE_ACCOUNT_ELIGIBILITY_CHANGED` | 409 | An account was disconnected mid-read. Read again. |
| `VENUE_ACCOUNT_REVERIFY_REQUIRED`, `VENUE_ACCOUNT_REVOKED` | 409 | No current venue key reads the account, or it was disconnected. Reconnect it in the app. |
| `VENUE_ACCOUNT_FUNDS_IN_WALLETS` | 409 | The money is in your own wallets: read those. |
| `INVENTORY_UNAVAILABLE`, `VENUE_ACCOUNT_ELIGIBILITY_UNAVAILABLE` | 503 | Retry shortly. |

  </Accordion>
  <Accordion title="Fee schedule">

| `error` | Status | What to do |
| --- | --- | --- |
| `INVALID_REQUEST` | 400 | The path's workspace id is not a UUID. |
| `FEE_SCHEDULE_UNAVAILABLE` | 503 | Unreadable; no partial or zero schedule is sent. Retry shortly. |

A key without Read fee schedule is refused with `403`.

  </Accordion>
</AccordionGroup>

Every other code is in [Error codes](/reference/error-codes).
