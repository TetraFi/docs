Read what each wallet and exchange account holds, and the TetraFi fees you pay. These reads never move money. Paths are under `/api/v1/workspaces/{workspaceId}`, with the `workspaceId` from [`GET /api/v1/me`](/api-reference/auth/get-current-credential) ([Permissions](/authentication#permissions)).

| Read | Permission |
| --- | --- |
| [Every balance](/api-reference/treasury/list-workspace-balances), one row per account, asset and chain: `GET …/balances` | Treasury read |
| [Your exchange accounts](/api-reference/treasury/list-accounts): [`GET …/accounts?kind=venueAccount`](/api-reference/treasury/list-accounts) | Treasury read |
| [One account's balances](/api-reference/treasury/list-workspace-balances): `GET …/balances?accountId={venueAccountId}`, from the venue now with `Cache-Control: no-cache` | Treasury read |
| [Where to deposit](/api-reference/venue-accounts/get-deposit-instructions) and [what was credited](/api-reference/venue-accounts/list-account-deposits): `…/deposit-instructions`, `…/deposit-history` | Treasury read |
| [Credit and positions](/trade/settlement-and-credit#credit-and-the-ledger): `…/credit` and `…/ledger` | Treasury read |
| [Fees](/api-reference/workspaces/get-fee-schedule) now and scheduled: [`GET …/fee-schedule`](/api-reference/workspaces/get-fee-schedule) | Read fee schedule |

## Every balance in one list

`GET …/balances` reads TetraFi's last observation and asks no chain or venue, unless you [read one exchange account now](#one-exchange-account). Filter with `asset`, `accountKind`, `accountId` and `network`; an account that cannot be stated is listed in `unreachable`, never as a zero row.

<AccordionGroup>
  <Accordion title="Fields and paging">
    Personal wallets are never listed; bank account balances cannot be observed.

<ResponseField name="id" type="string">Opaque: never parse or build one.</ResponseField>
<ResponseField name="accountKind" type="string">`wallet`, `venueAccount` or `bankAccount`; show an unknown kind as it is.</ResponseField>
<ResponseField name="accountId" type="string">A wallet's `walletId`, or the exchange account's `venueAccountId`.</ResponseField>
<ResponseField name="asset, network, networkRef" type="string">The asset; `network` is the CAIP-2 network, `null` off-chain (such as at an exchange) or when the source does not name exactly one; `networkRef` is the source's own network spelling.</ResponseField>
<ResponseField name="nativeAssetId" type="string">The asset's id at its source, such as a token contract, if known.</ResponseField>
<ResponseField name="amount" type="string">Everything held, locked included, a decimal string in whole units. Negative at an exchange account for what it owes.</ResponseField>
<ResponseField name="available" type="string">What you can spend or move now. At an exchange account, the venue's free amount less TetraFi's commitments to open trades and withdrawals. `null` when unknown.</ResponseField>
<ResponseField name="locked" type="string">What the provider itself holds back; `null` when it states none, such as on a credit line.</ResponseField>
<ResponseField name="observedAt, expiresAt" type="string">When the source observed it (an exchange: when it reported it), and when that reading stops being current; `expiresAt` is `null` when the source states no expiry.</ResponseField>
<ResponseField name="source" type="string">Where the reading came from, such as `providerApi`, `providerApiLastKnown` or `onChain`; `null` when unnamed. Treat an unknown value as other.</ResponseField>
<ResponseField name="freshness" type="string">`fresh`, `stale` or `partial` (treat an unknown value as `stale`).</ResponseField>
<ResponseField name="valueUsd, valuedAt" type="string">US dollar value and when its price was observed; both `null` without a reference price, never `0`.</ResponseField>

Page with `limit` (1 to 100) and `cursor` until `nextCursor` is `null`; if accounts change mid-paging, restart without a cursor.

  </Accordion>

  </Accordion>
  <Accordion title="Balances that are unknown">
    `unreachable` repeats on every page: show each account in it as unavailable, not empty. Each entry has a `source` (`wallets/…`, `venueAccounts/…` or `bankAccounts/…`) and a `reason`, with `accountKind`, `accountId`, `asset` and `networkRef` when known, and the `readAt` of the source's last answer.

    An entry with `source` `accessSettings` (`reason` `accessSettingsUnavailable`) means access settings could not be read, so the list may leave accounts out. Read again shortly.

## List your exchange accounts

`GET …/accounts?kind=venueAccount` lists your exchange accounts. Each item's `ref.resourceId` is the `venueAccountId` the reads below take.

<AccordionGroup>
  <Accordion title="Fields and paging">
    Page with `limit` (20 by default, at most 500) and `cursor` until `nextCursor` is `null`. Filter with `venue`, such as `binance`, or `environment`.

<ResponseField name="ref.resourceId" type="string">The `venueAccountId`. `ref` is absent when you may not read the account's detail.</ResponseField>
<ResponseField name="accountId" type="string">The account's own id in this list, for [`GET …/accounts/{accountId}`](/api-reference/treasury/get-account); not a `venueAccountId`.</ResponseField>
<ResponseField name="provider, displayName" type="string">The venue, such as `binance`, and the account's name in the app.</ResponseField>
<ResponseField name="environment" type="string">`production`, `testnet`, `sandbox` or `unknown`.</ResponseField>
<ResponseField name="readingState" type="object">How current its balances are: `status`, `freshness` and `observedAt`.</ResponseField>

  </Accordion>

## One exchange account

`GET …/balances?accountId={venueAccountId}` answers what the venue last reported for the account, one row per asset, with the [fields above](#every-balance-in-one-list). Add `Cache-Control: no-cache` to read the venue now: the rows answer from that reading. It needs exactly one exchange account in `accountId`; without one, or with another kind of account, it is refused `400 INVALID_REQUEST` naming `Cache-Control`.

<AccordionGroup>
  <Accordion title="Request and output">

<VenueBalances />

```json Example output (shortened)
{"rows":[{"asset":"0G","amount":"1630","available":"1630","locked":"0","valueUsd":null,"observedAt":"2026-11-23T10:45:27.006Z","source":"providerApi","freshness":"fresh"},…],"unreachable":[]}
{"rows":20,"observedAt":"2026-11-23T10:46:03.421Z","expiresAt":"2026-11-23T10:51:03.421Z","unreachable":[]}
```

A venue that refuses the read now answers a named error, such as `VENUE_CONNECTION_INVALID` when its key no longer verifies; the recorded rows still stand.

  </Accordion>
  <Accordion title="Deposits">

| Read | Answers |
| --- | --- |
| [`GET …/venue-accounts/{venueAccountId}/deposit-instructions`](/api-reference/venue-accounts/get-deposit-instructions) | The asset and network pairs it takes deposits on, in `options`. |
| [`GET …/venue-accounts/{venueAccountId}/deposit-history`](/api-reference/venue-accounts/list-account-deposits) | Deposits the venue credited, every asset and network in one request: `asset` and `network` (CAIP-2) are optional comma lists; omit them for the whole account. From `from` (RFC 3339, 1 to 30 whole days back, 7 by default) until now. The credits are in `items`, oldest first, each with its `asset` and `network`; without paging, the whole window. With `limit` (1 to 200), follow `nextCursor` until `null`; a cursor keeps its window. A pair not read is in `unreachable` with its `id`. Add `include=observation` for each pair's own window (`since`, `until`), status and reason in `included.observation[<pair>].value`. |

Empty `items` is truly empty only when `unreachable` is empty too; otherwise the history was not read, and its one `unreachable` entry names why in `reason`. A window of more than 1,000 venue records is not read (`DEPOSIT_HISTORY_WINDOW_TOO_LARGE`): read a shorter window.

<VenueDepositHistory />

```json Example output (shortened)
{"deposits":0,"pairs":[{"pair":"1INCH","status":"unsupported","since":"2026-11-15T12:34:28.283954Z"},…],"unreachable":[{"id":"1INCH","reason":"VENUE_ENDPOINT_UNAVAILABLE"},…]}
```

  </Accordion>
</AccordionGroup>

<Warning>
A venue that publishes no networks answers `options: []` and lists its assets in `unconfirmedNetworkAssets`. Their networks are not verified: never send real funds on them.
</Warning>

## Fee schedule

`GET …/fee-schedule` answers the schedule in force now (`current`) and every change already scheduled (`upcoming`); it reads only. Every member can read fees, but a key needs Read fee schedule: no other permission includes it.

<AccordionGroup>
  <Accordion title="Request and response">

<FeeScheduleRead />

```json Response (shortened)
{
  "workspaceId": "36ff6481-…",
  "current": {
    "defaultRates": {
      "platform": { "ratePpm": "100", "effectiveFrom": "2026-10-27T00:00:00Z" },
      "grossPlatform": { "ratePpm": "100", "effectiveFrom": "2026-10-27T00:00:00Z" },
      "takerIncentive": null,
      "makerShare": null
    },
    "venues": [],
    "partnerArrangementApplies": false
  },
  "upcoming": []
}
```

  </Accordion>
  <Accordion title="Schedule fields and rates">

<ResponseField name="current" type="object">
  The schedule in force.
  <Expandable title="schedule">
    <ResponseField name="defaultRates" type="object">The rates every venue uses unless it is listed in `venues`.</ResponseField>
    <ResponseField name="venues" type="array">The venues whose rates differ, each with its own `rates`.</ResponseField>
    <ResponseField name="partnerArrangementApplies" type="boolean">`true` when your workspace has a partner arrangement with the venue.</ResponseField>
  </Expandable>
</ResponseField>
<ResponseField name="upcoming" type="array">
  Scheduled changes, oldest first, each with its `effectiveFrom` and the whole `schedule` from then. `[]` means none.
</ResponseField>

| Rate | Meaning |
| --- | --- |
| `platform` | Your charged rate, after any taker incentive. |
| `grossPlatform` | The rate before the taker incentive. |
| `takerIncentive` | The share of the gross fee rebated to you; `null` if none. |
| `makerShare` | The fee share you earn as the venue's partner maker; `null` if none. Never shows another workspace's arrangement. |

Each rate has `ratePpm` and `effectiveFrom`:

- `ratePpm`: a decimal string in parts per million (100 ppm is one basis point, 0.01%). Read it as a decimal, not a float.
- `effectiveFrom`: the RFC 3339 date-time it applies from.

</Accordion>
</AccordionGroup>

## Refusals

<AccordionGroup>
  <Accordion title="Balances and exchange accounts">

| Status and `error` | What to do |
| --- | --- |
| `400 BALANCE_LIST_QUERY_INVALID` | Use only `cursor`, `limit`, `asset`, `accountKind` (`wallet`, `venueAccount` or `bankAccount`) and `accountId`. |
| `400 LIMIT_INVALID`, `400 CURSOR_INVALID` | Send a valid `limit`, or start again without a cursor. |
| `403 OBSERVATION_AUTHORITY_REQUIRED`, `403 VENUE_READ_AUTHORITY_REFUSED` | The key has no current authority to read the account, or lost it mid-read. Restore its Treasury read access. |
| `403 WALLET_ACCESS_CHANGED` | The key's access changed mid-read. Read again. |
| `403 WORKSPACE_ACCESS_REQUIRED` | The key's owner left the workspace. Use a current member's key. |
| `404 VENUE_ACCOUNT_NOT_FOUND` | No exchange account with that id in the workspace. |
| `409 VENUE_ACCOUNT_ELIGIBILITY_CHANGED` | An account was disconnected mid-read. Read again. |
| `409 VENUE_ACCOUNT_REVERIFY_REQUIRED`, `409 VENUE_ACCOUNT_REVOKED` | No current venue key reads the account, or it was disconnected. Reconnect it in the app. |
| `409 VENUE_ACCOUNT_FUNDS_IN_WALLETS` | The money is in your own wallets: read those. |
| `503 INVENTORY_UNAVAILABLE`, `503 VENUE_ACCOUNT_ELIGIBILITY_UNAVAILABLE` | Retry shortly. |

  </Accordion>
  <Accordion title="Fee schedule">

| Status and `error` | What to do |
| --- | --- |
| `400 INVALID_REQUEST` | The path's workspace id is malformed. |
| `503 FEE_SCHEDULE_UNAVAILABLE` | Unreadable; no partial or zero schedule is sent. Retry shortly. |

A key without Read fee schedule is refused with `403 INSUFFICIENT_SCOPE`.

  </Accordion>
</AccordionGroup>
