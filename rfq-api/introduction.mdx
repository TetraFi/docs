The RFQ API puts your request in front of every eligible solver and LP in your workspace. Each answers with a cryptographically firm, executable quote from its own inventory, settled through an escrow that delivers your output or refunds your input.

## When RFQ Is the Right Tool

* **Firm commitments** - each quote is signed and executable as-is, no re-pricing, no last look
* **Stablecoins and tokenized real-world assets**, where LP inventory is deepest ([coverage](/supported-chains))
* **Supported corridors at size**, where competing LP inventory beats on-chain routing

## Quick Reference

| Facet           |                                                                    |
| --------------- | ------------------------------------------------------------------ |
| Protocol        | REST over HTTPS                                                    |
| Credential      | API key (`X-API-Key` header)                                       |
| Signature       | EIP-712 over the `escrow-v0` payload                               |
| Landing the tx  | `apiSubmit` (TetraFi) or `walletBroadcast` (you)                   |
| Guarantee       | Every quote firm; every order escrow delivery-or-refund            |
| Effort          | Moderate: one signature plus a preflight round-trip                |

## The Shape of a Trade

Quotes compete, you pick one, preflight tells you what to do next; the quote's `executionMode` says who lands the transaction ([Execution Modes](/core-concepts/execution-modes)).

| # | Move               | Input                                                | Output                           |
| - | ------------------ | ---------------------------------------------------- | -------------------------------- |
| 1 | Collect quotes     | Intent (inputs, outputs) → `POST /api/v1/rfq/quotes` | Competing firm quotes, ranked    |
| 2 | Preflight the pick | Chosen quote → `POST /api/v1/rfq/orders/preflight`   | `nextActions` plan               |
| 3 | Authorize          | EIP-712 `escrow-v0` payload → taker wallet           | Signature                        |
| 4 | Hand it over       | Signed order → `POST /api/v1/rfq/orders`             | Order ID                         |
| 5 | Watch it land      | Order ID → `GET /api/v1/rfq/orders/{id}` or WebSocket | Status: `settled`               |

Under `walletBroadcast`, step 2 returns the prepared transaction and you send it from your own RPC.

## Endpoint Map

| Endpoint                             | Purpose                                              |
| ------------------------------------ | ---------------------------------------------------- |
| `POST /api/v1/rfq/quotes`            | Collect firm quotes from every eligible solver/LP    |
| `POST /api/v1/rfq/orders/preflight`  | Verify submit-readiness and fetch `nextActions`      |
| `POST /api/v1/rfq/orders`            | Submit the signed order for escrow settlement        |
| `GET /api/v1/rfq/orders/{id}`        | Follow the order through to delivery or refund       |

<Note>
  RFQ responses contain **only** firm solver/LP escrow quotes from workspace-approved LPs, never DEX, bridge, issuer, or indicative candidates; if none can quote, the answer is a typed product-unavailable, never a silent fallback ([Compliance Policy](/core-concepts/compliance-policy)). Multi-source routing is the [Router API](/router-api/introduction). Coming soon: a second firm quote per settlement, cleared at a deadline you pick at a tighter price ([integration shape](/netting-api/introduction)).
</Note>
