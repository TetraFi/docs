Your backend authenticates with an API key bound to you and one workspace. TetraFi checks your current permissions on every request, so if yours shrink, the key's shrink with them.

For software that should not depend on one person's account, use a [service account](/service-accounts).

## Create an API key

<Steps>
  <Step title="Open the form">
    In the app, open **Settings**. Under **Your account**, find **Personal API keys**, select **Open API keys**, then **Create key**.
  </Step>

  <Step title="Name it">
    Enter a **Name**. **Description**, **Expiration** and **IP allowlist** are optional unless your workspace requires keys to expire. A key without an expiration works until revoked.
  </Step>

  <Step title="Choose permissions">
    Tick what the key may do ([below](#permissions)). To quote and order: **Read quotes**, **Submit orders** and **Read orders**.
  </Step>

  <Step title="Turn on venue trading (to trade)">
    Switch **Venue trading** on. You must be a workspace owner or admin who manages credentials, signed in with a second factor.
  </Step>

  <Step title="Create and store it">
    Select **Create key**. Copy **API Key** and, with venue trading, **Request-signing secret** into your secret manager, separately. Both are shown once and cannot be recovered; never put them in source code or a tracked file.
  </Step>
</Steps>

## Permissions

A key can receive only permissions you hold in that workspace.

| Permission in the app | What the key can do |
| --- | --- |
| **Read quotes** | List assets and read prices. With **Submit orders**, request quotes: **Read quotes** alone cannot. |
| **Submit orders** | Place and cancel orders, and, with **Read quotes**, request quotes. |
| **Read orders** | Read an order's status and recover an order by its quote. |
| **Read trades** | Read the trade history. |
| **Treasury read** | Read [balances](/trade/balances), exchange accounts and credit. Never moves money. |
| **Read settlements** | Read [settlement](/trade/settlement-and-credit) plans, windows, obligations and movements. |
| **Read fee schedule** | Read your [fee schedule](/trade/fee-schedule). No other permission includes it. |
| **Read compliance** | Read your workspace's [capabilities](/before-you-trade#check-readiness-from-your-backend). |
| **Manage webhooks** | Create and manage [webhooks](/trade/webhooks). |

The [permission matrix](/reference/permissions) maps every operation to its scope.

## Trade on your venue accounts

Every quote you can order today is Basic: TetraFi executes it from your exchange or OTC venue account, or an organisation wallet granted to your key. A key that trades Basic quotes needs:

- **Venue trading**, given only at creation, with **Read quotes** and **Submit orders**, by its owner signed in with a second factor. It cannot be added to an existing key.
- **Request signing**, always on for a venue-trading key: every request must be [signed](#sign-requests). It cannot be turned off (`409 VENUE_TRADE_KEY_SIGNING_REQUIRED`); for unsigned requests, use a key without venue trading.
- **Organisation wallets granted to it**, to trade from them. **Create API key** grants your default organisation wallets you hold a Trade right on ([Give a key organisation wallets](/before-you-trade#give-a-key-organisation-wallets)). Venue accounts need no grant.

Without venue trading, a quote request still answers `200`, but your venue accounts read `restricted` with `venueTradeScopeRequired` and return no quotes.

### Check what a key can do

`GET /api/v1/me` has no side effects and describes the calling key, not a user profile. A signing key must sign it too.

| Field | What it says |
| --- | --- |
| `authKind`, `auth` | `apiKey`; `auth` is `oauthClientCredentials` for a [service-account token](/service-accounts). |
| `keyId`, `name`, `origin` | The key's identity. `keyId` is also its `credentialId`. |
| `scopes`, `permissions`, `dataScope` | Its current authority. |
| `workspaceId` | The workspace the key is bound to. |
| `organisationWallets` | Venue trading and wallet grants: `venueTradeScope` and `venueTradeEnabled` must both be `true` for venue-account quotes ([Check readiness](/before-you-trade#check-readiness-from-your-backend)). |
| `rateLimits`, `expiresAt` | The key's own request limit and expiry, when set. |

## Send the key

Send `X-API-Key: <your key>` on every request. Without credentials, a request answers `401 AUTH_REQUIRED` before anything is looked up.

- **`X-Workspace-Id`** is optional with a key. When sent, it must name the key's own workspace: `403 WORKSPACE_SCOPE_MISMATCH` otherwise, `400 INVALID_WORKSPACE_ID` when malformed. A signed-in member's session must always send it (`400 MISSING_WORKSPACE`).
- **Workspace paths** (`/api/v1/workspaces/{workspaceId}/…`: balances, trades, settlement, venue accounts, fee schedule, capabilities, webhooks) take the `workspaceId` from `GET /api/v1/me`. Quotes and orders do not.

## Sign requests

When signing is on, every request carries three more headers:

| Header | Value |
| --- | --- |
| `X-Timestamp` | The current Unix time in seconds: within 300 seconds of TetraFi's clock, and a write at most 10 seconds ahead. Keep your clock NTP-synced. |
| `X-Nonce` | On a write (`POST`, `PUT`, `PATCH`, `DELETE`) only: a fresh random value, 16 to 128 characters of `A-Z`, `a-z`, `0-9`, `-` and `_`. |
| `X-Signature` | The lower-case hexadecimal HMAC-SHA256 of the lines below, keyed with the signing secret's 32 bytes. The secret is 64 hexadecimal characters: decode it first. |

A write signs these five lines joined by newlines, with no trailing newline; a read leaves out the nonce line. A request without a body hashes zero bytes.

```text
<X-Timestamp>
<X-Nonce>
<HTTP method in upper case>
<path with its query string, exactly as sent>
<lower-case hexadecimal SHA-256 of the exact body bytes>
```

Generate the nonce from a cryptographic source, for example 18 random bytes in base64url:

<CodeGroup>
```bash Bash
nonce=$(openssl rand -base64 18 | tr '+/' '-_' | tr -d '=')
```

```javascript Node.js
crypto.randomBytes(18).toString('base64url')
```

```python Python
secrets.token_urlsafe(18)
```
</CodeGroup>

Each nonce is accepted once per key, by every TetraFi server, restarts included.

A retried write signs again with a new nonce and timestamp, keeping its `Idempotency-Key` and body ([Retries and recovery](/trade/retries-and-recovery)). A read has no nonce, so the same signed read is accepted again within 300 seconds: polling needs none.

A failed check answers `401 AUTH_REQUIRED` with `details.reason`:

| `details.reason` | What went wrong |
| --- | --- |
| `SIGNATURE_REQUIRED` | The key needs signing and a header is missing. |
| `SIGNATURE_INVALID` | The signature is malformed or does not match. |
| `TIMESTAMP_OUT_OF_RANGE` | `X-Timestamp` is more than 300 seconds off, or a write's is more than 10 seconds ahead. |
| `NONCE_REQUIRED`, `NONCE_INVALID` | A write has no `X-Nonce`, or it is malformed or the header appears twice. |
| `SIGNATURE_REPLAYED` | This nonce was already accepted for the key. |

### Rotate the signing secret

Only the app's signed-in session rotates or enables signing, never your backend's key. `POST /api/v1/workspaces/{workspaceId}/credentials/{credentialId}/signing`, with the key's `keyId` as `credentialId`, answers a new `signingSecret` once and replaces the old one at once.

Only the key's owner (or, for a service-account key, a member who manages credentials) may call it. An API key or service-account token is refused with `403 JWT_REQUIRED`.

## Rotate and revoke

- **Rotate key** issues a new key; the old key keeps working for one hour while you deploy the new one. The rotated key keeps its permissions and its signing secret.
- **Revoke key** is permanent: within at most 30 seconds the key is refused with `401 AUTH_REQUIRED` and `details.reason` `INVALID_API_KEY`.

Quote and other rate limits are on [Rate limits](/reference/rate-limits).

## If something goes wrong

<AccordionGroup>
  <Accordion title="401 AUTH_REQUIRED with API_KEY_EXPIRED">
    The key is past its expiration.
  </Accordion>

  <Accordion title="429 on a replayed request">
    The rate limit is checked first: a replay sent while the key is rate limited answers `429`.
  </Accordion>

  <Accordion title="503 API_KEY_UNAVAILABLE">
    The key or its signing state could not be confirmed. The nonce may have been recorded: sign again with a new timestamp and nonce before you retry.
  </Accordion>
</AccordionGroup>
